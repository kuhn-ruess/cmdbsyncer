{# Key/value editor for the label conditions of the Checkmk Setup Rule form. The Host label and Service label conditions are stored as text: "key:value", several labels comma separated, all of them must match. This shows every label as a compact key : value chip in one wrapping line, "+" adds a label, "x" removes one, and writes the text back on every change, so storage and export read the same text as before. Keys and values are suggested by the view's _label_suggestions endpoint (labels other Setup Rules use, host labels also the attributes of the hosts). Jinja works in both inputs. A value that cannot be split into key and value (e.g. one Jinja expression rendering all labels) stays in the plain text field, the text button switches at any time. Colours use the theme --surface-* tokens with light fallbacks so every theme renders it. #} {# The JavaScript handles Jinja delimiters as plain text. #} {% raw %} {% endraw %}
