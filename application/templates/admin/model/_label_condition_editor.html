{# Key/value editor for the label conditions of the Checkmk Setup Rule form. The Host label and Service label conditions are stored as text, "key:value" (Service label: several, comma separated, all must match). This puts a key and a value input per label in front of the field and writes the text back on every change, so nothing about storage or export changes. Keys and values are suggested by the view's _label_suggestions endpoint (labels other Setup Rules use, host labels also the attributes of the hosts). Jinja works in both inputs. A value that cannot be split into key and value (e.g. one Jinja expression rendering all labels) stays in the plain text field, "Edit as text" switches at any time. Colours use the theme --surface-* tokens with light fallbacks so every theme renders it. #} {# The JavaScript handles Jinja delimiters as plain text. #} {% raw %} {% endraw %}
