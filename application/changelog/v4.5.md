# Version 4.5

## Unreleased

- INCOMPATIBLE: SEC: A new password now also revokes the personal API tokens of that user, whether changed by the user, reset by mail or set by an admin. Automation using such a token gets a 401 until its owner logs in with the new password and creates a new token under Profile, API Tokens. The old token stays in the list, marked as revoked
- INCOMPATIBLE: Rules: Tag Match `equal` ignores upper and lower case again, as documented and as all other conditions do; a condition on `os` also finds an attribute called `OS`. Rules whose attribute name differs only in case did not match since version 3.12.12 and match after this update, so check them before you update
- INCOMPATIBLE: Rules: a Hostname Match regex with an upper case class like `\D`, `\S` or `\W` no longer does the opposite of what it says; such a regex was turned into `\d`, `\s` or `\w` before matching. Hostname regexes keep ignoring upper and lower case
- INCOMPATIBLE: SEC: Changing or resetting a password now ends all other sessions of that user, also when an admin sets it in the user management. Everyone with a local password has to log in once after this update
- INCOMPATIBLE: SEC: Ansible is updated from 10.5 to 14.6 to close two known vulnerabilities. The server running Ansible now needs Python 3.12 or newer and the target hosts Python 3.9 or newer. Own playbooks need a check: a condition (`when`) must now give a real true or false, a plain string or number stops the task. The bundled playbooks are adapted, Extra Vars like `cmk_register_bakery=true` work with them
- INCOMPATIBLE: SEC: MCP over SSE: the new setting `MCP_ALLOWED_HOSTS` lists the host names the server answers to beside localhost; a remote client or a reverse proxy that passes on its own host name needs it, any other name is refused
- INCOMPATIBLE: SEC: Accounts and users can no longer be exported or imported through the REST API or MCP, because they hold credentials and password hashes; use the `rules export_all_rules` and `rules import_rules` commands
- INCOMPATIBLE: SEC: MCP: a read-only user can no longer change anything, a user limited to accounts or templates only reaches those hosts and none of the accounts, rules, logs and cron groups, and only a global admin without such a limit can read an account with its password
- INCOMPATIBLE: SEC: Container image: cron groups run again; since 4.4.0 the scheduled run failed before it started, without any message. The jobs now run as the unprivileged user `app` instead of root
- INCOMPATIBLE: Cron Groups: a task that failed, like a Checkmk export that could not connect, now counts as failed; before, the group showed success and the following tasks ran, set Continue on error if they should still run
- INCOMPATIBLE: SEC: Jinja templates: on Python 3.11 and older, `datetime` could be used to break out of the sandbox and run code on the server; `datetime.datetime.now()` and the like keep working
- INCOMPATIBLE: Filter rules: a host set to Ignore is now also left out when a rule on the attributes works with a timestamp; before, it was exported anyway
- INCOMPATIBLE: Rewrite and Custom Attribute rules: `{{ FIRST_MATCHING_TAG }}` and the documented `{{ FIRST_MATCHING_VALUE }}` now hold what the first matching condition of the rule matched; before they had no value unless the rule debug setting was on, the misspelled `FIST_MATCHING_VALUE` keeps working
- INCOMPATIBLE: CSV and NetBox imports: with `delete_host_if_not_found_on_import`, an import with errors or without any hosts no longer archives hosts; it says so in the log instead
- INCOMPATIBLE: i-doit export: objects of another type or CMDB status, or without active monitoring, are recognized as existing and no longer created again in every run; an object with the same title and another type now counts as existing too
- INCOMPATIBLE: SEC: Password reset: a reset no longer logs in, so 2FA can't be bypassed with the mail alone; a disabled user gets no reset mail, can't use an old link and loses a running session right away; the new setting `PUBLIC_URL` fixes the address in the link, which otherwise depends on the Host header of the request
- INCOMPATIBLE: SEC: Archive: it now needs the Hosts, Objects or hard delete permission; before, every logged-in user could open it and restore hosts. A user restricted to accounts or templates can no longer open, restore or permanently delete archived hosts of others, and restoring a single host can no longer be triggered by a mere link
- FEAT: Checkmk Server Sites: a server can run one site per CMK Server Settings, for example a production and a test site; a site name is unique per server instead of overall. Run Playbook runs each settings with only its own sites, as does the inventory `cmk_sites:<settings name>`. Existing installations allow it after `cmdbsyncer sys self_configure`
- FEAT: Files: Checkmk installation packages (.deb, .rpm, .cma) can be uploaded, to be used as staging directory of the CMK Server Settings
- FEAT: Manage OMD Server: the log names the full path on the Ansible controller where the installation file is looked for and whether it was found
- FEAT: Checkmk DCD Rules: the export corrects an existing connection whose site, title, comment, disabled state or restricted source hosts no longer match the rule; Checkmk cannot change a connection, so it is deleted and created again, its hosts stay. A connection for a site Checkmk does not know is kept and reported, as is a DCD ID that renders differently for several hosts
- FEAT: Checkmk DCD Rules: {{ HOST_SITE }} gives the site the host export gives the host, from a site attribute, a Site Pool or its folder options, else the site of the account; the Site field suggests it. {{ cmk_site }} alone is always the site of the account
- FIX: Checkmk: the rule export names the rulesets it compares and calls that step a comparison instead of a cleanup, because it only changes what it lists as an update or delete
- FIX: Checkmk: a changed title, topic or help of a tag group now reaches Checkmk; before, the export called the group up to date as long as its tags were the same
- SEC: Accounts: a proxy password with a special character is masked in the debug output, and a proxy setting without a scheme no longer ends up in the log with its password
- SEC: Checkmk: the debug page of a Setup Rule, the user generation preview and the folder pages no longer show account passwords a rule refers to, a user with only the Checkmk role could read them there
- SEC: Ansible for Windows targets no longer installs the `kerberos` package, which has a known vulnerability without a fixed version; Kerberos login keeps working through `pykerberos`
- FIX: Checkmk: when moving a host to another folder fails, the export now says so and skips that host, instead of reporting it as moved
- FIX: VMware: a run closes its session on vCenter when it ends, and a VM deleted during the run only skips that VM instead of ending the run
- FIX: Imports: ODBC skips a row without a hostname, YML takes a group without variables, and Jira OnPrem reads more than one page; before, each of these ended the import with an error
- FIX: Checkmk: Sync Folder Pools also resets a pool all hosts have left to zero seats, such a pool could look full
- FIX: Filter rules: Whitelist Attribute with an exact name no longer drops an attribute whose value is 0 or False, such an attribute now reaches the export
- FIX: Lowercase Hostnames: the inventory tree and open label approvals of a renamed host stay with it instead of being removed by the next maintenance, and its cached rule results are rebuilt with the new name
- FIX: Inventory: `inventorize_match_by_domain` no longer hits hosts whose name only happens to end the same way: `srv1` matches `srv1` and `a.srv1`, not `testsrv1`
- FIX: Maintenance: `dont_delete_hosts_if_more_then` stops only when more hosts than the given number would be archived, as documented; a run with exactly that number was stopped too
- FIX: Hosts: Stale since shows the day the host was found stale, not a date from before it
- FIX: Ansible: the site update of the Checkmk server playbook no longer stops at the downtime calculation when it runs in the container image, and setting the downtime no longer shows up as failed
- FIX: Checkmk: a process that hangs while calculating a host or its tags, or while fetching the hosts of a folder or an inventory, no longer blocks the host export, the tag export or Inventorize forever: after the timeout the run goes on, the affected host stays unchanged and no tag gets removed. When all processes hang, the log says so and the run ends instead of waiting once per remaining host
- FIX: Cron Groups: the log now shows when a group that failed runs clean again; the entry was never written
- FIX: Cron Groups: a time window over midnight, like from 22 to 4, now runs; before, such a group never started
- FIX: REST API: the relations of a host no longer end in a server error when one of them still points at a deleted host
- FIX: REST API: a host the account refuses (invalid hostname, shadow source, inventorize only) or a blank hostname now gets a 400 instead of a server error; `/objects/bulk` lists such a host under `not-saved` and goes on with the others
- SEC: Checkmk host debug page: an attribute value is no longer evaluated as a template, so a value from a source system can't show account passwords there
- FIX: Checkmk Inventorize: a host whose HW/SW inventory query times out or fails keeps its existing inventory instead of losing it
- FIX: Rewrite Attributes: renaming an attribute with the value 0, False or empty no longer removes it, and With Split can split at a colon (`::1`); a split pattern that makes no sense keeps the old value instead of stopping the run with an error
- FIX: Netbox interface rules: an empty interface name is now skipped; with a list variable it stopped the whole export with an error, without one it created an interface called SKIP_RULE
- FIX: Checkmk: when Checkmk can't be reached, the commands report a clear connection error instead of ending with a traceback
- SEC: MCP login: when several users match the same login name, the response time no longer tells which of them exists, and such a collision now appears in the audit log as it does for the REST API
- FIX: REST API: `GET /objects/all` without `start` no longer leaves out the first host; `limit=0` is refused with a 400 instead of returning a next link to itself, and pages keep a fixed order
- FIX: Checkmk: the tag export no longer aborts when a host ignored by a filter rule meets a tag rule with Multiply by List
- SEC: Autocreate Rules: an attribute value from a source system can no longer add fields to the created rule; a value with a quote, backslash or line break now arrives unchanged, and a host ignored by a filter rule no longer stops the run
- SEC: Users with a forced password change now have to change it before they can open any other page, not only the start page; the REST API and MCP are not affected
- FIX: Jira Cloud import and export no longer stop after 1000 objects, the Cisco DNA import no longer stops after 500 devices
- FIX: i-doit: a category with ten or more entries keeps all of them, before later entries overwrote the first ones; the description set by a rule now reaches the created object instead of `undefined`
- FIX: Cron: a run requested by webhook, the Run button or the API while the group is running is no longer lost; it starts in the next pass after the current run has ended
- FEAT: Rules: every rule list with an Export now has an Import next to it: paste a rules file or give the path of one in the Files folder. Check shows per rule what would happen, an existing rule stays unless Replace existing rules is set, one bad record means nothing is imported, and a file of another rule type is refused. The export now names its rule type in the first line and every export file carries the name of its rule model. Lookup Tables get Export and Import as well
- FEAT: Checkmk: new area Manage Service Labels: rules in the GUI set labels on the services of a host, with Jinja templates that can also rebuild the value of an existing label, and `checkmk export_service_labels` writes them to Checkmk. The new Inventorize source Labels per Service reads the labels of each service separately. A rule keeps existing while a host no longer matches only because the label is already set. The host debug page lists the output of each matching rule: service or regex, label name and value
- SEC: Updated the libraries joserfc, tablib, pylint, mcp and python-ldap to versions without known vulnerabilities
- SEC: The docker compose files now use MongoDB 8.0.34 instead of 8.0.4; existing data is taken over by the restart
- SEC: Approval of critical labels (`APPROVAL_REQUIRED_LABELS`): Bulk Edit Labels no longer gets around it, and nobody can approve their own change; without that setting nothing changes
- SEC: Rules in Git: a rule file or folder in the repository that is a symbolic link is refused, so whoever can push there can't overwrite or read files of the Syncer server
- SEC: Hosts: the values in View Cache Details now need the Account Management permission, as cached rule results can contain account credentials; the debug page of a host also hides the i-doit API token and the Checkmk bakery passphrase
- SEC: Saved searches and other names in confirmation dialogs can no longer run code in the browser of whoever clicks on them; shared saved searches can only be changed by their owner or a global admin, and the Cancel button of bulk forms only leads back into the syncer
- SEC: Users restricted to accounts or templates: bulk actions, details and edit of objects, the debug, timeline, inventory and relations pages, Copy as new and the approval queue no longer reach hosts outside the restriction; Set Template only offers their templates, and Re-apply to matching hosts is no longer available to them
- FIX: Host list: the bulk action Set Template only adds the template; an imported host stays with its account and keeps being updated by the import, before it became CMDB managed and later imports skipped it
- FIX: `request-runner run_request_file` sends each saved request once with its own method; before, every line was sent as GET, POST, PUT and DELETE, which could delete what the same line had just created
- FIX: Checkmk rule export: with several accounts exported one after the other, as in a cron group, rules of one account no longer end up in the Checkmk of the next
- FIX: Checkmk rule export: a Value Template that renders to no valid Python value, like an unquoted word, no longer aborts the whole export. The export names the rule and continues, and a rule that already exists in Checkmk stays as it is
- FIX: Checkmk rule export: with rules of one ruleset in several folders and a Folder Index set, the reorder moved them into a wrong folder and every other run deleted and recreated them. Rules are now only sorted inside their own folder, and rules that were moved are put back by the next export
- FIX: Checkmk export: the action Don't Update no longer aborts the whole export when the host already exists in Checkmk
- FIX: NetBox export: a device or virtual machine whose export failed, because of an API error or a faulty rule, is no longer set to decommissioning; it stays unchanged and the log names it
- FIX: CSV and NetBox imports: `delete_host_if_not_found_on_import` no longer archives hosts with `no_autodelete` set
- FIX: Archive: a restored host is no longer archived again by the next stale check or maintenance run; the days until it counts as unseen start anew with the restore
- FIX: Checkmk export: a host whose rules could not be calculated, because of a timeout or a faulty rule, is no longer deleted from Checkmk; it stays unchanged and the log names it
- FIX: Checkmk Groups and User Generation: a rule without an outcome no longer breaks its list or the export
- FIX: Switching a value directly in the list works again for Users and Rule Automations, instead of failing with an error
- SEC: Rules in Git: the address of a Git Repository account can no longer pass options to git and run commands on the server
- SEC: Users: without being a global admin you can no longer make anyone a global admin, change or delete a user with more rights than you, grant roles you don't hold, lift or see a restriction to accounts or templates, or read 2FA secrets
- SEC: Notifications: title and message templates can no longer run code on the server
- FEAT: Rules from a pasted list: Aggregate by column joins the rows with the same value into one, the other columns become lists, e.g. one row per hostname with the list of its domains
- FEAT: Checkmk Setup Rules: with the new option Create missing Hosts, the export of the rules creates the hosts named in Condition — Host name as CMDB hosts if the Syncer does not know them yet, with the CMDB Templates given in Templates of created Hosts
- FEAT: Shadow Source: the log shows after an import how many of the delivered hosts are not in the Syncer, with up to 100 of their names
- FEAT: Start page: the Run button of a cron group queues it without reloading the page
- FEAT: Start page: Recent Errors now sits at the top of the page, above Data flow and Cron Jobs
- FIX: Cron Groups: the interval offers Custom interval in minutes, and the minutes field only shows up and counts with it; before, minutes entered next to e.g. Every hour silently replaced the chosen interval, the list shows Every N minutes for such groups
- FEAT: Rules in Git: push the rules of selected types from a test instance into a Git repository and pull them into production, from the page Modules → Syncer Rules → Rules in Git, with `rules git_push` / `rules git_pull` or the cronjob Syncer: Pull Rules from Git; the pull can delete the rules missing in the repository, the repository is set up as an account of the new type Git Repository
- FEAT: Checkmk Settings: a Run Playbook button on every entry, and the list action Run Manage OMD Server, install or update Checkmk right from the settings, only on the servers of the enabled sites that use them; the list shows only name, documentation, version and server user
- FEAT: New OP5 Monitor import: `op5 import_hosts` and `op5 inventorize_hosts` read all hosts with address, alias, host groups, contacts, contact groups, parents and custom variables from an account of type OP5 Monitor
- FEAT: New Ansible playbook `deploy_configs/install/install_redhat.yml` installs the Syncer on RedHat, Rocky or Alma with MongoDB, Gunicorn and Apache, either as its own virtual host or under a sub-path, served over HTTPS
- FEAT: API: the cron status (`/api/v1/syncer/cron/`) tells whether a cron group is enabled, so the Checkmk plugin no longer monitors disabled or deleted cron groups
- FEAT: Checkmk: new Manage LDAP Connections maintains the LDAP connections Checkmk logs its users in with, including contact groups and roles from directory groups; server and bind password come from an LDAP account, `checkmk export_ldap_connections` creates, updates or removes them
- FEAT: `rules export_all_rules --zip` writes the export compressed into a zip archive, and `rules import_rules` reads such an archive back as it is
- FEAT: Checkmk Settings: Fill in from checkmk.com loads the current Checkmk versions on click and fills in version, edition and the filename of the installation file for the chosen platform, including the Checkmk Appliance; a new Download Proxy is used for the download of the installation file and for this list
- FEAT: Checkmk Setup Rules: the new option Per Template evaluates a rule once per CMDB template of the host, each time with only that template's labels, so a contact group and the services of one template no longer mix with those of another template on the same host; the host debug page shows these rules per template
- FEAT: The account list is grouped by account type, each group under a heading with the type's name and its number of accounts that folds the group away like the Global Custom Attributes, with Expand all and Collapse all; sorting by a column shows the plain list
- FEAT: Browser tab titles name the page first, e.g. "Edit web01 · Hosts · Objects" or "Filter · Rules · Ansible", so open tabs can be told apart
- FEAT: Host list: new filter Checkmk Attribute Key:Value finds hosts by the attributes of their last Checkmk sync, the green label badges
- FEAT: Host list: show up to 500 hosts per page
- FEAT: Host list: new action Remove Template takes one CMDB template off the selected hosts and keeps their other templates
- FEAT: Lookup Tables: maintain a long key/value list in the UI and read it in any Jinja field with `{{ lookup('table', key) }}`, e.g. to set an attribute from the value of another one
- FEAT: Custom Attributes and Rewrite Attributes: a Jinja help next to the template fields lists the lookup tables, variables, functions and filters and inserts them with one click
- FEAT: Global Custom Attributes: the rule list is grouped by the attribute each rule sets (a rule with several attributes in a group of that combination), shows every rule's place in the order the rules run, and the order can be changed by drag and drop or with the arrow keys, including moving a rule into another attribute's group. Each group folds away with a click on its heading
- FEAT: Secret Store: the Checkmk password store is now Modules > Secret Store and holds passwords, tokens and certificates for every module, global or bound to a host. Rules reach a host's entry with `{{ secret('key') }}` (plaintext with `{{ secret_value('key') }}`), entries of an archived host are kept as orphaned and can be bound to another host, certificates are shown for copying, and the host overview lists the entries of the host with masked values. New roles: Secret Store, and Secret Store: show plaintext values. Users limited to accounts or templates only reach entries of their own hosts, never global ones. Lookup Tables and the Secret Store sit at the bottom of the Modules menu
- FEAT: Host import: Import CSV / YAML also takes YAML files (several at once, several hosts per file as a list or as documents separated by ---, also YAML-like files whose certificate lines are out of indentation), and "Bulk add hosts" is now "Add hosts manually" with a format switch (auto, host list, CSV, YAML, key/value list)
- FEAT: Host import preview: every import and every manual add opens a preview where the values of each host, added columns and a template per host can be edited, chosen columns go into the Secret Store instead of becoming labels, and the account of the imported hosts is picked. Users limited to accounts only get their own accounts and cannot overwrite hosts outside their scope
- FEAT: Checkmk Setup Rules: the Jinja help sits next to the Value Template and the Folder, the new placeholder `{{ HOST_FOLDER }}` puts a rule into the folder its host lands in (rules per host only), and the Host label and Service label conditions are entered as compact key and value pairs with suggestions from the existing labels. The Host label condition now takes several labels as well, all of them must match
- FEAT: Checkmk > Folders and Folder Options: the folders the host export would use, with the hosts landing in each and the folder options (contact groups, permissions, title, ...) sent to Checkmk, per Checkmk account. The debug of a folder shows which host and which Export Rule with which conditions gave which option and how the values merge. Calculated from the syncer alone without touching Checkmk or the pools, users limited to accounts or templates only see the folders and options of their own hosts
- FEAT: Checkmk menu sorted into groups with dividers: the host export rules with the Pools first, then the rules for setup rules, groups, tags, users, downtimes, notifications, DCD and BI, then the Checkmk Server and the inventory from Checkmk, and at the bottom the views to check the result (Folders and Folder Options, Preview Generated Users, Data Quality Check, Cache). The menus are a little denser so the long ones fit the screen
- FEAT: Checkmk > Data Quality > Configuration Checks: pick a Checkmk account and the checks to run and see the problems they find, split by topic with a summary of the counts on top, and download them as a PDF report in the syncer design (needs the optional package fpdf2 from the extras, the page works without it). The first check looks at the HTTP checks: services that are WARN, CRIT or UNKNOWN in the monitoring right now with their output and the rule behind them, the same URL checked twice, website and certificate checked by two separate checks that one check_httpv2 check can do, and old check_http rules that are not migrated or still run next to their migrated rule. The checks only read from Checkmk. The Data Quality Check moved into the same Data Quality submenu
- FEAT: Accounts: the list shows only the custom fields that have a value, the first four of them with the rest folded away; the form lists one compact row per field, folds the fields without a value away on edit and shows their help as an info icon
- FEAT: ServiceNow: a failed request shows the whole call in debug mode and on the query page — URL with parameters, all headers with secrets masked, the proxy really used and whether it comes from the account or the environment
- FEAT: Accounts: a new import source can run as "Shadow Source" next to the current one — its data is stored beside the hosts without changing them, and the host details and Debug Host compare it with the live data and the rule outcomes; the shadow data can be cleared from the account and host list
- FEAT: Checkmk DCD Rules: the text fields have the Jinja help, and {{ HOST_FOLDER }} gives the folder the host export puts the host in and {{ HOST_POOL_SITE }} the site its site pool assigned
- FEAT: Checkmk Setup Rules: the Jinja help of the value shows how a password in the rule points to an entry of the Secret Store
- FIX: Files: creating a folder, uploading, renaming or editing a file works again when the syncer runs under a sub-path such as /cmdbsyncer — the dialog sent its form to the address without that path
