# Version 4.3

## Version 4.3.1
- FIX: The Checkmk rule export writes each host once instead of five times while it calculates the rules, which takes a large inventory a lot less time the first time it runs after a rule change
- FIX: A "Loop over List" that renders a single entry creates one rule for that entry again instead of one rule per letter of it
- FIX: The Checkmk rule export no longer gets slower the longer it runs — "Loop over Hosts and collect distinct rules" stayed fast for a few thousand rules and turned into minutes beyond that, which an outcome looping over a list reached quickly
- FIX: The "Loop over List" field of the Checkmk Setup rules and tag groups takes Jinja as well — a plain attribute name keeps working, and an expression rendering to a list or a comma separated string now creates one rule or group per entry
- FIX: The JSON log stream carries everything a command or cron run reports — the retries, the timeouts, the result per host, every cron pass — while a run on a terminal keeps its readable output; it stays off until it is switched on under Config → Local Config
- FIX: A ServiceNow inventorize run reads the relationship table once per query instead of once per table, so several tables matched by relation no longer page through cmdb_rel_ci again and again

- FEAT: Hosts with uppercase letters in their name can be renamed to lowercase — a "Lowercase all hostnames" button on the Data Quality dashboard showing how many are affected and how many of them are archived, with a "Show affected hosts" button listing every rename, the archived entries and the names blocked by an existing host, and a new `sys lowercase_hostnames` CLI command printing the same information (dry run by default, `--apply` to write)
- FEAT: New Checkmk "Data Quality Check" page — paste a list of hostnames or upload a CSV and check them against a Checkmk account to see which hosts are present, which exist under a different name/domain, whether their agent works (the Check_MK service state) and which contact groups may see them, or scan a whole account for hosts with uppercase letters in their name or without a fully-qualified name (FQDN); the result can be copied or exported as CSV, and the page has its own permission so a user can be given it alone without any other part of the Checkmk section

### ServiceNow
- FEAT: ServiceNow tables whose records belong to a server — network adapters, clusters, databases — can be attached to that host instead of being imported as hosts of their own: name each table either with the record field that references the server or with `rel` to look the host up in ServiceNow's relationship table, and the new `service_now inventorize_data` run stores every record as inventory data of the host it belongs to — a record referencing a server by its short name still finds the host the import created with a domain appended. Each inventorized table has its own "inventorize_query" limiting which records it delivers and "inventorize_fields" limiting which of their fields are read, so a wide table can be cut down to the handful of fields that are wanted
- FEAT: New ServiceNow entry in the web interface queries a table read only — it shows the fields a record really has, which name the objects would be imported under and which records would be skipped, and table, API path, query, field list and hostname field can be tried out per query before they go into an account
- FEAT: New ServiceNow plugin imports hosts from the ServiceNow Table API (e.g. cmdb_ci_server) — configure the tables, hostname field and an optional query on the account, run via CLI or cron; the account option "api_path" puts the table path behind the context path of an API gateway sitting in front of the instance instead of always asking for /api/now

### LDAP
- FEAT: New LDAP entry in the web interface searches a directory read only — a search for a hostname without domain also finds the object that carries the domain, objects can be looked up by any attribute or with an own filter, and base DN, attributes and encoding can be tried out per search before they go into an account
- FEAT: The inventorize output names the full DN next to the hostname when the source delivers one (LDAP), so it is visible which directory object the data came from
- FEAT: New `ldap debug_query` command to try out LDAP search filters and queries — it shows what an account's query returns, which objects would become hosts and which are skipped, and takes `--base-dn`, `--search-filter` and `--attributes` to test a change without touching the account; `--list-attributes` instead lists which attributes the found objects actually have, in how many of them, and an example value, so the attribute list of the account can be filled from a real result

### Jira Cloud
- FIX: The Jira Cloud export no longer rewrites Status, Reference and User fields on every run — their current value in Jira was read as empty, so every export reported a change even when nothing had changed

### Projects
- FEAT: A Project steers its hosts and its rules to accounts separately — new "Export RULES to Accounts" / "Never export RULES to Accounts" lists let you promote a project's rules on their own schedule (e.g. to test first, production later) while its hosts stay unchanged (an empty rule list falls back to the host list)
- FEAT: Hosts and rules assigned to a Project are no longer limited by a Checkmk account's folder scope ("Limit Host Export to Folders") — the project's account lists alone decide where they go, so a single host or rule can reach a test instance without opening up its whole folder

### Logging
- FEAT: The JSON log stream can be switched on for command runs as well, so imports, exports and cron runs reach the log collector instead of only the web application — set JSON_LOGGING_CLI in local_config.py
- FIX: The structured log record now carries everything the Log view shows — a detail key that occurs more than once, one error per failed host for example, kept only its last value, and the traceback was missing entirely
- FIX: The logging configured in local_config.py is applied again — a syslog target or a log file set through the LOGGING key was silently ignored since 3.8.2 and never received a single entry
- FIX: Every entry of a sync run is now really written to the configured external log target, not only to the Log view in the interface
- FIX: The LOG_LEVEL key works again and raises the log level of both loggers without having to restate the whole LOGGING configuration
- FIX: The log entry of the Database Maintenance run shows only its title; the account and its settings are now part of the entry details

### Database & Maintenance
- FEAT: New command `./cmdbsyncer sys label_history` shows what the label history costs and which label key and host fill it, so a churning label can be found and fixed
- FEAT: New command `./cmdbsyncer sys purge_label_history` cleans the label history up — entries older than the retention, optionally limited to one collection, or `--all` to drop it completely and get the disk space back right away; dry run by default, `--apply` to delete
- FEAT: New command `./cmdbsyncer sys db_stats` shows what occupies the space in MongoDB — totals plus every collection with its document count, data size, size on disk and index size, biggest first; `--indexes` adds the size of each index, `--collection <name>` lists that collection's largest documents, and collections that keep growing (log, label history, audit log, Ansible run history, inventory trees) are pointed out below the table
- FEAT: The maintenance run now also permanently deletes hosts that have been in the archive for longer than a retention period (default 30 days), configurable per maintenance account via the `purge_archived_after_days` setting (set it to `0` to keep archived hosts forever)
- FIX: The backup history is no longer kept forever (`BACKUP_HISTORY_RETENTION_DAYS`, default 365 days), the metrics endpoint no longer reads the whole host list on every scrape, and an expired self-approval grant now disappears from the list instead of lingering
- FIX: Self-approval grants can be created for more than one user again, and a secret store that accounts still pull their password from can no longer be deleted out from under them; run `cmdbsyncer sys self_configure` once to clear the leftover index
- FIX: The inventory trees no longer carry a second index on the host name that MongoDB never used but had to update on every write; `cmdbsyncer sys self_configure` removes it from existing installations
- FIX: Deleting a host now also removes its inventory tree, closes its open field approvals and drops the relations other hosts had pointing at it — on every deletion path, not just in the archive; a host whose relation partner was already deleted no longer breaks the host detail view and the relations graph, and the maintenance run cleans up what earlier versions left behind
- FIX: The Ansible run history, the decided field approvals, the audit log and the decided approval-queue entries are no longer kept forever — each has a retention (configurable under Config → Local Config → Retention) that MongoDB enforces on its own
- FIX: Label changes made by an import are no longer written to the audit log by default — an import that rewrites labels on every run produced one entry per host per run and buried the changes people made; `AUDIT_IMPORT_LABEL_CHANGES` turns them back on
- FIX: The label history behind the host "Timeline" tab no longer grows without limit — it is off by default (`LABEL_HISTORY_ENABLED`), and the Timeline icon and tab are only shown when it is enabled; it writes one entry per host save instead of one per changed label, and MongoDB drops entries older than `LABEL_HISTORY_RETENTION_DAYS` (default 90) on its own; on installations whose import rewrote labels on every run it had grown into the largest collection of the database by far

### Security
- SEC: The audit log no longer records the values of password, secret, token and private-key fields — among them the Checkmk automation secret and the webserver private key from the Checkmk Settings; "Scrub secrets from stored diffs" in the Audit Log cleans up entries written earlier, and any secret that was recorded should be rotated
- SEC: A host name containing HTML is no longer rendered as markup in the host list's log column
- SEC: Account passwords are masked on the host debug page — a rule outcome using `{{ACCOUNT:<name>:password}}` no longer reveals the secret to users who only hold a plugin role; exports keep resolving it normally
- SEC: A custom SQL query can no longer smuggle statements past the validation inside SQL comments
