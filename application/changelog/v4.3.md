# Version 4.3

## Unreleased
- FEAT: The Checkmk Data Quality report shows for every host whether it is known in the CMDB and which template it carries there, and a template can be given to the hosts that already exist afterwards — templates already on a host are kept
- FEAT: The Checkmk Data Quality page lets a domain name be given when missing hosts are created — hosts entered without a domain get it appended, hosts already given as an FQDN stay unchanged — and the CMDB template can be picked by typing instead of scrolling a long list
- FEAT: New LDAP entry in the web interface searches a directory read only — a search for a hostname without domain also finds the object that carries the domain, objects can be looked up by any attribute or with an own filter, and base DN, attributes and encoding can be tried out per search before they go into an account
- FEAT: The rule import takes an `--override` switch which replaces rules that already exist instead of skipping them, so a rule file can be imported again after a change (also available in the API and MCP import)
- FEAT: The inventorize output names the full DN next to the hostname when the source delivers one (LDAP), so it is visible which directory object the data came from
- FEAT: New account option "Restrict to" limits an account to one direction — "Only Import" blocks every inventorize run with it, "Only Inventorize" keeps it from importing hosts of its own, so a wrong command or cron entry stops with a clear error instead of writing data
- FEAT: New `ldap debug_query` command to try out LDAP search filters and queries — it shows what an account's query returns, which objects would become hosts and which are skipped, and takes `--base-dn`, `--search-filter` and `--attributes` to test a change without touching the account; `--list-attributes` instead lists which attributes the found objects actually have, in how many of them, and an example value, so the attribute list of the account can be filled from a real result
- FEAT: The Move to Folder and Create Empty Folder actions have an editor for the folder attributes — one card per folder level with fields for title, contact groups, site, labels and the usual tags, instead of hand-writing the `|{...}` dict
- FEAT: The host debug page shows the folder options as a tree — one row per folder level with the attributes set on it, so a nested folder structure shows which level actually gets which attribute
- FIX: The rule optimization never rewrites a Setup Rule outcome that produces more than one Checkmk rule — swapping its host list for one group's label gave that condition to the other rules too, so every host carrying the label collected all of their values (for example every contact group that shares a service list)
- FEAT: The CMDB template list shows the attributes in a clear structure — one row per attribute with its value(s) as separate chips, so a comma-separated list wraps over several lines instead of being cut off, and the columns a template never uses are gone
- FEAT: Editing CMDB attributes shows one line per attribute instead of a card per entry, and the value field takes the full width of the form so a long attribute value is readable while typing
- FEAT: Admin pages use the whole window width instead of a fixed 1140 pixel column — wide lists and long values no longer sit squeezed in the middle of an empty screen
- FIX: Reordering Checkmk rules now only moves the rules that are actually out of place instead of every rule of the ruleset — an export that appeared to hang in "Reorder syncer rules" on a large ruleset sends no requests at all when the order is already right
- FEAT: The reorder step shows progress per moved rule and how many moves it will make, and can be switched off entirely with the Checkmk account option `skip_rule_reorder`
- FEAT: The rule optimization analysis is available in the web interface — reachable from the Setup Rules list, it runs in the background (it walks every host twice), refreshes itself while running, and each finding can be applied with one click
- FEAT: New `hash` filter for Jinja templates turns a value that cannot be a Checkmk label — a comma-separated list, a value with spaces, a service pattern — into a short stable one that can
- FEAT: `checkmk analyse_rules` also suggests hashed labels for attributes whose value cannot be a label on its own, and `--apply` creates the rewrite rule that builds them; `--hash-labels` keeps raw attribute values out of Checkmk entirely
- FIX: `checkmk analyse_rules` no longer suggests replacing a host list with a label in rulesets where Checkmk discards host label conditions — the rule would have been left without any condition and applied to every host in the folder
- FEAT: New `checkmk analyse_rules` command names the Setup Rules whose export ends up listing hundreds of hostnames in one condition, and tells you which host attribute covers exactly the same hosts, so the rule can use a label condition instead. With `--apply` it makes the change for you, including letting the attribute through the export filter. Reads the database only, sends nothing to Checkmk, and the account is optional
- FIX: A host entering or leaving a Checkmk rule that covers many hosts at once now adjusts that rule instead of deleting and recreating it — a single changed host no longer makes the whole rule look obsolete
- FEAT: The Checkmk rules export says why it deletes a rule — folder, comment, condition or value drift, or a duplicate in Checkmk — and closes with a count per reason; `--debug` adds the concrete difference for each one
- FEAT: `sys delete_inventory` takes a `--hostname` to clear the inventory of a single host instead of the whole database, and drops the cached export data of the hosts it touches
- FIX: The Checkmk rules export keeps going when a request times out — only the affected ruleset is skipped for that run (and left untouched rather than filled with duplicates), everything else is exported as usual
- FIX: Editing, archiving or deleting a CMDB template counts towards the open changes in the top bar now, the same way a rule change does — the template feeds its values into every host carrying it
- FIX: The Checkmk group export no longer stops when Checkmk refuses to delete a group that is still in use — the group is reported and the export continues, and the deletion is retried on the next run
